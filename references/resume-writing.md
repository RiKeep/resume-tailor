# 简历写作方法

在 JD 分析清单基础上，把用户真实素材改写成有针对性、可量化、一页内的简历内容。

## 1. 真实性红线（最高优先级）

- 只改写**已发生的事实**：不编造经历、公司、职位、时间、证书、数据。
- 允许的优化：调整措辞、突出重点、对齐 JD 关键词、把口语化描述专业化、补全可由事实直接推出的量化口径。
- 不允许的操作：无中生有、夸大职级（参与→主导）、把课程作业包装成线上项目、虚构数据。
- 素材中没有的内容标"待用户确认"，不静默填充。

## 2. 内容取舍与排序

- 与 JD 强相关的项目/技能**前置并详写**，弱相关的简写或合并，无关的删除。
- 模块顺序按岗位调整：技术岗通常 教育→技能→项目/实习→校园→评价；职能岗可把实习/工作经历前置。
- 每段经历控制在 2–4 条，每条只讲一个信息点，避免堆砌。

## 3. 单条经历的写法

结构：**动作动词 + 做了什么 + 怎么做/用什么 + 结果（尽量量化）**

- 用动词开头：设计、开发、优化、重构、对接、排查、搭建、负责、推动。
- 用 STAR 组织：情境/任务→行动→结果，文字压缩为一句话。
- 能量化就量化：性能提升百分比、用户/数据量、接口数量、覆盖人数、节省时间。
- 量化数据必须来自素材或可由事实直接推出；没有数据时写清产出物和影响，不硬凑。

示例（基于真实素材的合理改写）：
- 弱：负责商城系统的开发。
- 强：基于 Spring Boot + MySQL 独立完成商城订单模块 8 个接口开发，支撑课程演示 30+ 人同时使用。

## 4. 技能区块

- 按类别分组（后端/框架/数据库/工具/语言），不要罗列无关技能凑数。
- 熟练度与事实一致，优先写 JD 点名的技能。
- 证书写明全称和通过情况，没有就不写。

## 5. 一页纸与排版

- 目标 A4 一页：内容超一页时，先压缩弱相关条目和重复表述，不靠缩小字号硬塞。
- 严格保留模板 CSS：不改字体、颜色、间距；只替换文字，必要时按模板既有结构增删条目。
- 增删条目后检查对齐：时间/单位/职位三段对齐，列表符号一致。

## 6. 语言风格

- 简洁、书面、主动语态，一句一义，去掉"我""了""的"等冗余。
- 自我评价避免空泛形容词，用 2–3 条事实性总结（熟悉什么、能做什么、特质+佐证）。
- 技术名、英文缩写保持规范写法，大小写与通用写法一致。

## 7. 交付前自检

- 跑 `scripts/check_all.py <resume.html> --expect <目标页数>`，确认：
  - 无漏填的正文容器、无占位标记、无失效引用；
  - 渲染页数等于目标页数，且页面为 A4。
  若返回 3（`[SKIP]`，本机无 Chrome/Edge），必须改用浏览器打开并截图人工核对，不得跳过。
- 页数超出时只精简文字，不要调字号或页边距；**不要因此回头重写文字稿**（除非用户主动要求）。
- 人工核对：无溢出错位、照片正常、三段对齐、列表符号一致。
- 逐条回看 JD 必备关键词是否都在简历中有对应事实。
