# JD 分析与匹配方法

生成简历前先完成 JD 拆解。目标是让简历内容与岗位要求逐条对齐，而不是写一份通用简历。

## 1. 把 JD 拆成五层

| 层级 | 内容 | 简历落点 |
| --- | --- | --- |
| 硬门槛 | 学历、专业、毕业时间、工作年限、城市 | 基本信息/教育背景，不符要先提示用户 |
| 硬技能 | 技术栈、框架、工具、语言、证书 | 技能区块 + 项目经历中体现 |
| 工作职责 | 日常要做什么（动词短语） | 实习/项目经历的职责描述 |
| 软技能/素质 | 沟通、抗压、协作、自驱等 | 自我评价 + 经历中的事实佐证 |
| 加分项 | 优先条件、特定行业经验 | 有则前置，无则不写 |

## 2. 提取关键词

- 优先抓**名词短语**：技术名（如 Spring Boot、MySQL、Redis、微服务）、工具、业务领域、证书。
- 再抓**动作词**：负责、设计、优化、对接、排查、搭建、推动。
- 记录 JD 里的**原词原写法**（如"高并发""接口联调""需求分析"），简历中尽量用同一措辞，便于通过 ATS 和人工筛选。
- 按出现频次和位置（标题/必备/加分）判断权重，区分"必备"与"加分"。

## 3. 建立匹配矩阵

对每条关键要求，对照用户素材标注：

- **匹配**：有直接对应事实 → 详写，用 JD 原词。
- **部分匹配**：有可迁移经验 → 用可迁移技能表达，突出共性（如"校园系统的用户模块"对接"后台管理系统开发"）。
- **缺失**：无任何事实支撑 → 不写、不编造；若为硬门槛缺失，明确告知用户风险，由其决定是否投递。

## 4. 缺失项处理红线

- 禁止虚构技术栈、项目、公司、任职时间、量化数据。
- 禁止把"了解/接触过"包装成"精通/主导"。
- 技能熟练度要与素材一致：用过→熟悉，深入实践→熟练，主导设计→精通。
- 拿不准的事实，先问用户，不自行脑补。

## 5. 输出物

分析完成后，在进入写作前形成一份简短清单（内部使用，不必交付）：
1. JD 必备关键词列表（按权重排序）
2. 匹配 / 部分匹配 / 缺失 三栏
3. 建议前置和详写的素材
4. 需要向用户确认的疑点
